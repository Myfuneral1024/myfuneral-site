www.myfuneral.co.kr · 저장소 `Myfuneral1024/myfuneral-site` (공개) · `main` 브랜치 / (root) → GitHub Pages

## 1. 구성
- **원본은 `_src/src.html` 한 파일**이다. 안에 CSS · 8개 화면 HTML · 스크립트가 다 들어 있다.
- **스크립트 · 스타일 파일 이름은 내용 해시** (`assets/site.<해시>.js/.css`, 최근 8판 보관 · `assets/versions.json`). 2026-10-19 휴대폰에 남아 있던 예전 페이지가 새 스크립트를 받아 날짜 계산이 멈춘 일 때문 (GitHub Pages는 `?v=`를 무시함). `site.js` · `site.css`도 최신본으로 같이 쓴다(예전 페이지용). 해시 파일을 손으로 지우지 않는다.
- 공개 파일은 `python3 _src/build.py`로 만든다. **공개 파일을 직접 고치지 않는다**:
  `index.html`, `urgent/ nobinso/ price/ print/ clan/ chon/ manners/`의 `index.html`, `assets/site.css`, `assets/site.js`, `sitemap.xml`, `404.html`
- 그대로 두는 파일: `CNAME`(www.myfuneral.co.kr), `favicon.svg`, `apple-touch-icon.png`, `og.png`(카톡 공유 그림), `robots.txt`, `naverb64ba87306a5179497b82d3c875bb21e.html`(네이버 소유확인 — 지우면 안 됨), `assets/fonts/chosungs.woff`(조선궁서체)
- `_src/`는 밑줄로 시작해 GitHub Pages에 공개되지 않는다.

### build.py가 하는 일
- CSS · JS를 `assets/`로 분리, 페이지마다 그 화면 `<section>`만 넣음 (검색 노출용).
- 페이지별 title · description · canonical · og (`META` 표), 메뉴 `aria-current`, `href="#price"` → `/price/`.
- 스크립트의 `route()`를 주소 기반(`body[data-route]`)으로 바꾸고, 시작 블록을 화면별 준비 코드로 바꾼다.
  화면 사이 넘김: `/print/?clan=번호`, `/print/?rel=관계`, `/print/?tab=env`.
  - **입력한 내용은 어디에도 저장하지 않는다** (사용자 요청 2026-10-18: 다시 뽑을 때 걸리적거림). sessionStorage · localStorage를 쓰지 말 것. 시작 블록이 예전에 저장된 `mf-hist` · `mf-ps` · `mf-pr` · `mf-ch`를 지운다.
- 출력실 페이지에만 jsPDF와 서식 서체(Shippori Mincho · Yuji Syuku · 조선궁서체) 링크.
- 모든 페이지에 speculationrules prefetch, 처음 페이지에 네이버 확인 태그 · 옛 `#주소` → 새 주소 이동 · JSON-LD.
- `sitemap.xml`(8개 주소), `404.html`(옛 Framer 주소 `/services` → `/price/` 등).
- **build.py는 src.html의 특정 코드를 글자 그대로 찾아 바꾼다** (`one()`가 정확히 1번인지 확인). src.html의 `/* ── 화면 이동 ── */` 블록이나 `/* ── 시작 ── */` 블록, `clanCard` · `jibangLink`를 고치면 build.py도 같이 맞춘다.
- 메인 스크립트는 `<script>` 다음 줄이 `(function(){`로 시작해야 한다. head 안 짧은 인라인 스크립트는 줄바꿈 없이 쓴다.

### 유골함 (2026-10-19 사용자 선택)
- 메뉴가 길어지지 않게 **유골함은 메뉴 칸에 넣지 않고 흐름 속에 넣었다** (「무료 도구 ▾」로 묶는 안은 사용자가 고르지 않음). 메뉴는 8칸 그대로.
- `/urn/` 화면: 일반함 · 진공함 단면 그림(인라인 SVG, 색은 CSS 변수라 어두운 화면 대응) + 비교, 모실 곳별(봉안당 · 봉안묘 · 자연장 · 해양장), 비용, 자주 묻는 질문. build.py `ROUTES`에 `urn`이 있고, 메뉴에 없는 화면은 `aria-current`를 건너뛴다.
- 연결: 처음 화면 「모시는 장례」 목록, 장례가 발생하면 「가족이 챙겨 두실 것」, 무빈소 FAQ, 비용 계산 「꼭 알아 두실 것」과 유골함 질문의 링크.
- 기본 상품(무빈소 60 · 가족장 70)에 **유골함은 들어 있지 않다**. 진공함은 **45만원부터 400만원까지**(재질 · 마감에 따라).
- 비용 계산: 장의 차량 다음에 「화장 후 모실 유골함은 어떻게 할까요?」(매장이면 건너뜀, 고르기 전 다음 막힘) — 진공 유골함 +45만원부터 / 따로 준비했어요 / 필요 없어요 / 상담 때 정할게요. 견적에는 45만원(가장 낮은 금액)으로 넣고 「450,000원부터」로 보이며, 견적 화면 · 견적 글에 「고르시는 함에 따라 400만원까지」 안내.
- 「자연장은 생분해 용기만」(장사법 시행령), 「영구 보존」 같은 단정은 쓰지 않는다.
- 사용자 확인 필요: 일반 유골함 · 자연장용 함도 파는지와 금액(있으면 비용 계산 선택지에 추가), 봉안당 칸 크기 대신 확인 · 갖고 계신 함 사용을 실제로 해 주는지.

## 2. 고치는 순서
1. `_src/src.html`만 고친다. 여러 군데면 Python 치환 + `assert s.count(old)==1`.
2. `python3 _src/build.py` (확인용 따로: `--out /tmp/x`)
3. `python3 -m http.server 8771` (저장소 폴더) → Playwright Chromium으로 확인
   - 8개 페이지 × 1280×900, 390×844 · pageerror 0 · 가로 스크롤 없음
   - 끝까지 스크롤한 뒤 `main` 안에 opacity 0으로 남은 것 없음 (스크롤 효과)
   - 출력실: 종교마다 위패 미리보기, 명정 예시, 상중 안내문, 축문 캡처를 Read로 열어 눈으로 본다
   - 비용 계산: 다음/이전/고치기 · 연타 · 합계 · 마지막 견적 화면
   - 화면 사이 넘김: 본관 → 출력실, 촌수 지도 → 지방, 조문 예절 → 부의 봉투
4. 배포: 저장소 연결돼 있으면 commit · push 후 `git clone`해서 확인. 아니면 저장소 전체를 '올릴파일' 폴더로 압축해 보내고, 사용자가 올린 뒤 `git clone --depth 1` + `diff -rq`로 빠진 파일 확인 (**assets 폴더가 통째로 빠진 적 있음**).
5. 이 작업 환경의 셸에서는 www.myfuneral.co.kr · 구글 폰트 · jsdelivr 접속이 막힌다. 실제 사이트 확인은 WebFetch나 사용자 컴퓨터의 브라우저(연결돼 있을 때)로.

## 3. 출력실 서식 규칙
- **지방 (일반)** — 본관 · 성은 한자, 이름은 넣지 않는다.
  아버지 `顯考學生府君神位` · 어머니 `顯妣孺人南陽洪氏神位`(본관 넣기 선택) · 남동생 `亡弟學生府君神位` · 아들 `亡子秀才○○之靈`(이름 칸 값) · 합설은 두 칸.
- **종교 위패** (경쟁사 하늘휴 sjb.gaondnc.com/jibang/ 구성을 기준으로):
  - 기독교: 빨간 십자가 + 직분 + `故 성명`(세로) + 양옆 요한복음 11:25–26 「나는 부활이요 생명이니 나를 믿는 자는 죽더라도 / 살겠고 살아서 믿는 자는 영원히 죽지 않을 것이다.」 · 8.5×25.5cm 고정 · A4에 2장
  - 천주교: 검은 십자가 + 세례명 + `故 성명` + 양옆 「주여 망자에게 영원한 안식을 주소서 / 영원한 빛을 그에게 비추소서」 · 8.5×25.5cm
  - SGI: `妙法 성명 之靈` · 4×17.5cm (하늘휴의 SGI 마크 그림은 단체 로고라 넣지 않음)
  - 불교: `先嚴父/先慈母/故 + 本貫 + 后人/孺人 + (법명) + 성명 + 靈駕` · 원불교: 일원상(○) + `(법호) 성명 영가` · 기타: `故 + 本貫姓 + 公/氏 + 靈位`
  - 불교 · 원불교 문구는 확실한 근거를 못 찾아 사용자 확인을 기다리는 중.
  - 「문구 직접 고치기」: 어느 종교든 줄 단위(한 줄 = 한 칸)로 덮어쓰기.
- **명정** — 출력하지 않는다. 「명정 예시」: 종교 6개를 나란히 + 한자 · 읽는 법 목록.

## 4-1. 날짜 계산 (`/date/`)
- 돌아가신 날(양력) + 장례 기간(2~5일장, 기본 3일장) 또는 발인일 직접 입력.
- 발인 = 돌아가신 날 + (n−1)일 · 삼우제 = 발인일 + 2 (발인 날 초우 → 재우 → 삼우) · 49재 = 돌아가신 날 + 48 (돌아가신 날을 1일로) · 7재 = +6, +13 … +48 · 100일 = +99.
- 기일: 돌아가신 날의 음력 월 · 일 → 해마다 양력 날짜(`solarOf`). 윤달에 돌아가셨으면 평달 같은 날, 그해 그 달이 29일까지면 그믐(29일)로. 1주기 = 소상, 2주기 = 대상. 오늘 이후 6해를 표로.
- 음력 달력: 날마다 음력 일, 음력 초하루는 「월.1」, 손 없는 날(음력 9 · 10 · 19 · 20 · 29 · 30일) 회색 + 「손 없음」, 계산한 날 표시.
- 「가족용 / 장례지도사용」(2026-10-19 사용자 요청): 장례지도사용은 고인 성함 + 담당 장례지도사(이름 · 연락처, 최대 4명, 직함은 이름 칸에 같이 써도 됨)를 넣으면 화면 제목 · 이미지 · 복사 글에 들어간다. 저장하지 않는다.
- 「이미지 저장」(1080px 세로 PNG, 견적 이미지와 같은 모양: 로고 · 날짜 목록 · 담당 장례지도사 · 1661-4214) · 「이미지 공유 (카톡 등)」(navigator.share 파일 공유가 되는 휴대폰에서만 보임, 이미지를 미리 만들어 두었다가 바로 공유) · 「글로 복사」.
- 음력 표 `LM`은 2016-01 ~ 2040-12 (파이썬 `korean-lunar-calendar`로 만들고 예전 표 49개와 모두 일치 확인). 축문 간지도 이 표를 쓴다. 범위를 넓히려면 같은 방법으로 다시 만든다.
- **장례 후 서류 · 신고 기한** (2026-10-19 사용자 선택, `#after` · `dtAfter` · `renderAfter` · `afterText`): 돌아가신 날 기준
  - 사망신고 = 같은 날짜 +1개월 (가족관계등록법 84조, 「안 날부터」) · 상속 포기 · 한정승인 = +3개월 (민법 1019조, 「안 날부터」)
  - 상속세 신고 · 납부 / 부동산 상속 취득세 / 자동차 상속 이전 = 돌아가신 달의 말일부터 6개월 → 6달 뒤 그달 말일 (상증법 67조 · 지방세법 20조 · 자동차등록령 26조1항3호, 외국 거주 9개월)
  - 안심상속 원스톱 = 돌아가신 달의 말일부터 1년 → 12달 뒤 그달 말일 · 국민연금 유족연금 · 사망일시금 = +5년 (국민연금법 115조 소멸시효)
  - 「~개월」은 민법 160조대로 같은 날짜, 그 달에 그 날이 없으면 말일 (`isoMonths(s,n)`), 「말일부터」는 `isoMonths(s,n,true)`. 주말 · 공휴일 연장은 날짜에 넣지 않고 안내 글로만.
  - 화면에 「쉽게 셈한 날짜 · 기관에 확인 · 상속은 전문가 상담」 안내. 「서류 기한 글로 복사」. 날짜 안내 이미지에는 넣지 않았다.
  - 장례가 발생하면 「장례를 마친 뒤」에 「상속 · 세금 기한」 + `/date/#after` 버튼 (`href="#date" data-goto="after"`를 build.py가 바꿈).
- 근거: 삼우제 「발인 날짜 + 2일」(장례 업체 안내 다수), 49재 「돌아가신 날을 1일로」(부고 서비스 안내), 기제는 기일 새벽(한국민족문화대백과 「기제」), 요즘은 기일 저녁이 많음. 절 · 집안마다 다를 수 있다고 화면에 안내.
